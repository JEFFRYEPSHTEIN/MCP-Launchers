# Команды для всех MCP

Откройте PowerShell в корневой папке репозитория. Сначала создайте `.runtime\servers.json` по инструкции в [README.md](README.md), указав пути к MCP-серверам на этом ПК.

> [!IMPORTANT]
> **Перед `Start All` обязательно выберите рабочую папку.** `projectDirectory` в карте — папка установки MCP. Для файлов нужен `allowedDirectory` в конфиге Filesystem; для сборки — `projectRoot` в Rojo или ARC-профиле. Папку можно задать сразу и сменить позже, применив настройки. [Пошаговая инструкция](WORKING-FOLDERS.md).

```powershell
.\MCP-Commands.ps1 Help
```

Запуск всех четырёх MCP и вывод актуальных HTTPS-ссылок:

```powershell
.\MCP-Commands.ps1 Start All
```

По одному:

```powershell
.\MCP-Commands.ps1 Start Filesystem
.\MCP-Commands.ps1 Start Blender
.\MCP-Commands.ps1 Start Roblox-Studio
.\MCP-Commands.ps1 Start Rojo
```

Проверка и управление:

```powershell
.\MCP-Commands.ps1 Status All       # HTTPS, MCP и доступность приложения
.\MCP-Commands.ps1 Links All        # Только проверенные текущие ссылки
.\MCP-Commands.ps1 Restart Blender # Перезапуск выбранного MCP и его туннеля
.\MCP-Commands.ps1 Stop All         # Штатная остановка серверов и туннелей
```

Во всех командах `All` можно заменить на `Filesystem`, `Blender`, `Roblox-Studio` или `Rojo`. `Stop` оставляет окна Blender и Studio открытыми. Он также останавливает синхронизацию, которую запустил сам Rojo MCP. Отдельный `Arc-Commands.ps1 Serve` завершается через Ctrl+C в его окне.

Чтобы получить токен, запустите нужный сервер командой `Start` и найдите в выводе строку `Key/settings file:`. Откройте указанный `connection.md` в папке именно этого MCP-сервера и скопируйте оттуда значение токена. У Filesystem, Blender, Roblox Studio и Rojo разные токены. Скрипт использует ключ сервера и только сообщает путь к его файлу.

Для быстрого получения уже созданного токена откройте `Get-MCP-Token.cmd` двойным щелчком и вставьте полный путь к программе или папке её MCP-сервера. Ключ скопируется в буфер обмена. Программа по указанному пути не запускается; сервер может быть остановлен.

В корне репозитория также есть готовые файлы для каждого сервера: `Token-Filesystem.cmd`, `Token-Blender.cmd`, `Token-Roblox-Studio.cmd`, `Token-Rojo.cmd` и `Token-CMD.cmd`. Откройте нужный двойным щелчком — вводить путь не требуется. Ключ скопируется в буфер обмена, а окно останется открытым с результатом. Запускайте один файл нужного сервера за раз. Для полного заголовка можно вызвать, например, `.\Token-Rojo.cmd -Header`; `-Show` явно разрешает вывод значения в консоль.

```powershell
.\Get-MCP-Token.ps1 'C:\путь к программе\blender.exe'
.\Get-MCP-Token.ps1 'C:\путь к программе\RobloxStudioBeta.exe'
.\Get-MCP-Token.ps1 'C:\путь к программе\rojo.exe'
.\Get-MCP-Token.ps1 'C:\путь к\filesystem-mcp'
```

По известному имени исполняемого файла выбирается соответствующий MCP из вашей локальной карты серверов. Для общего `node.exe` используйте путь к конкретной папке MCP или укажите сервер явно:

```powershell
.\Get-MCP-Token.ps1 -Server Filesystem
.\Get-MCP-Token.ps1 -Server Blender
.\Get-MCP-Token.ps1 -Server Roblox-Studio
.\Get-MCP-Token.ps1 -Server Rojo
```

Параметр `-Header` копирует готовую строку `Authorization: Bearer <токен>`. Без него копируется только ключ для отдельного поля Token. Параметр `-Show` явно разрешает вывод выбранного значения в консоль вместо буфера обмена; можно присвоить его переменной: `$token = .\Get-MCP-Token.ps1 -Server Blender -Show`. Параметр `-MappingPath` задаёт другую карту серверов. Команда читает существующий `.runtime\config.json` выбранного MCP, сохраняет ключи и настройки, не обращается в сеть и не пишет секреты в файлы репозитория.

Для отдельно установленного CMD / PC Control MCP ключ хранится в другой папке. Когда он уже создан этим сервером, скопируйте его так:

```powershell
.\Token-CMD.cmd
```

Если файл находится в нестандартной папке, укажите `.\Token-CMD.cmd -TokenFilePath 'C:\путь к\token.json'`. По умолчанию помощник `Get-CMD-MCP-Token.ps1` использует `PC_MCP_DATA_DIR` или `%LOCALAPPDATA%\PcControlMcp\token.json`. Он проверяет сохранённый ключ, не создавая новый. Эквивалентная команда PowerShell:

```powershell
$cmdDataDirectory = if ($env:PC_MCP_DATA_DIR) { $env:PC_MCP_DATA_DIR } else { Join-Path $env:LOCALAPPDATA 'PcControlMcp' }
(Get-Content -LiteralPath (Join-Path $cmdDataDirectory 'token.json') -Raw | ConvertFrom-Json).token | Set-Clipboard
```

Если при запуске CMD MCP папка данных задавалась отдельным параметром, присвойте её путь переменной `$cmdDataDirectory`. Команды Launcher и `Get-MCP-Token.ps1` рассчитаны на Filesystem, Blender, Roblox Studio и Rojo; CMD MCP использует собственные скрипты запуска. Не загружайте его `token.json` на GitHub.

В Notion для соответствующего custom MCP добавьте выданный HTTPS URL с окончанием `/mcp` и настройте HTTP заголовок `Authorization` со значением `Bearer <токен>`. Если форма разделяет Prefix и Token, укажите `Bearer` в Prefix, а в Token вставьте только значение ключа. Это статическая авторизация заголовком; не вставляйте ключ в OAuth scopes. Notion описывает header-based authentication в [документации MCP connections](https://www.notion.com/help/mcp-connections-for-custom-agents).

При смене временного домена обновите URL в Notion, оставив тот же токен. Токен не является GitHub personal access token и не хранится в этом репозитории. Не публикуйте `connection.md`, `.runtime/` или значения ключей. Ссылки последней команды Start/Restart/Links записываются в приватный `.runtime/links.txt`; если выбрано одно подключение, файл содержит только его результат. Закрытие PowerShell после Start оставляет серверы работающими; ПК должен быть включён.

`Start` проверяет шлюз и HTTPS. Для проверки приложения выполните `Status`: он действительно вызывает MCP, а не только `/health`. Метки: `READY` — проверка прошла; `ATTENTION` — MCP отвечает, но нужен Place в Studio или выбран другой проект; `FAILED` — запрос завершился ошибкой. Ответ Blender с текстом `Error` считается ошибкой, даже если шлюз доступен. Синхронизация Rojo может быть остановлена при работающем MCP; это указано отдельно. Проверка не меняет файлы, сцены или Place. Ключи не выводятся и не записываются в диагностический отчёт.

Для Blender откройте нужный `.blend` и включите сервер в панели Blender MCP. При работающем шлюзе команда Start повторно использует его и сама не переключает сцену. Если запускается полностью остановленный Blender MCP, исходный помощник может открыть Blender с начальной сценой; затем откройте нужный файл. Safe Mode сохраняется.

Для Roblox Studio откройте Place и включите **Assistant → … → Manage MCP Servers → Enable Studio as MCP server**. При настроенном локальном профиле можно открыть указанный в нём Place:

```powershell
& '.\Arc-Commands.ps1' Studio
```

При наличии локального профиля Start/Restart Rojo использует выбранную папку проекта и указанный в профиле Rojo. Изменение конфигурации сохраняет ключ, создаёт приватную резервную копию и использует штатную остановку. Для сборки в новый файл и локальной синхронизации смотрите [ARC-COMMANDS.md](ARC-COMMANDS.md). Инструмент `rojo_serve` в Notion запускает синхронизацию, управляемую MCP.

Если Windows запрещает запуск `.ps1`, выполните команду в отдельном процессе, разрешив скрипты только для него:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\MCP-Commands.ps1 Start All
```

Для запуска с двойным щелчком есть `Start-All.cmd`, `Filesystem.cmd`, `Blender.cmd`, `Roblox-Studio.cmd` и `Rojo.cmd`. Если настроен ARC-профиль, используйте `MCP-Commands.ps1 Start All` или `Start Rojo` / `Restart Rojo`: эти команды применяют выбранный профиль. Прямой `Start-All.cmd` его не применяет.

Если после аварийного завершения сохранилась запись `running=true`, команды проверяют оба файла владельца, отсутствие записанного процесса и отсутствие TCP-слушателя на настроенном порту. Только при однозначном подтверждении остановки они сохраняют резервную копию записи и разрешают штатный запуск. При живом процессе, занятом порте или неполных данных команда завершится ошибкой. Параметр `-NoRecovery` запрещает такое восстановление. Не удаляйте файлы владельца вручную.

Старые ярлыки и новые команды возвращают ненулевой код при ошибке. Выделение временного домена ещё не означает готовность: запуск ждёт регистрации туннеля и успешной проверки HTTPS. Если туннель недоступен, посмотрите журнал соответствующего сервера и подключение сети; локальный MCP при этом может продолжать работать. После успешного перезапуска получите новые ссылки командой `Links All` и обновите их в Notion.

Все команды читают установленные серверы из `.runtime/servers.json`. Для другого ПК используйте `servers.example.json` и пути к своим установленным MCP. Команды не устанавливают серверы или приложения. ARC-профиль необязателен и применяется только с основной локальной картой серверов. Диагностике нужен Node.js и SDK из `node_modules` хотя бы одного установленного MCP. Подробный результат Status сохраняется в `.runtime/mcp-command-status.json`. Код завершения ненулевой при ошибке или необходимом действии, например отсутствии Studio Place.

Не загружайте на GitHub `.runtime/`, `connection.md`, ключи, резервные копии и локальные логи. Пути в этом документе служат примерами; настройки вашего ПК находятся в игнорируемой `.runtime/`.
